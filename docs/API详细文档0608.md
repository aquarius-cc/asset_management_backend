## 二、认证与授权

### 2.1 认证方式

系统采用 **JWT (JSON Web Token)** 认证机制，通过 [SimpleJWT](https://django-rest-framework-simplejwt.readthedocs.io/) 实现。

**双 Token 机制：**

| Token 类型 | 有效期 | 用途 |
|------------|--------|------|
| `access_token` | 短期（默认 2 小时） | 访问 API 资源，放在请求头中 |
| `refresh_token` | 长期（默认 7 天） | 用于刷新 access_token |

### 2.2 获取 Token

通过登录接口获取 Token：

```
POST /api/v1/auth/login/
```

成功响应中包含 `access` 和 `refresh` 两个 Token。

### 2.3 请求头格式

所有需要认证的接口，必须在请求头中携带 `access_token`：

```
Authorization: Bearer <access_token>
```

**示例：**

```http
GET /api/v1/auth/profile/ HTTP/1.1
Host: localhost:8000
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
Content-Type: application/json
```

### 2.4 Token 刷新

当 `access_token` 过期后，使用 `refresh_token` 获取新的 `access_token`：

```
POST /api/v1/auth/token/refresh/
```

```json
{
  "refresh": "<refresh_token>"
}
```

### 2.5 权限级别

| 权限级别 | 说明 | 适用范围 |
|----------|------|----------|
| `AllowAny` | 允许所有用户访问（含未认证） | 注册、登录、Token 获取/刷新/验证 |
| `IsAuthenticated` | 需要有效 Token | 大部分业务接口 |
| `IsAdminUser` | 需要管理员权限 | 部门/员工的创建、修改、删除操作 |

### 2.6 认证错误示例

**未认证（401）：**

```json
{
  "code": 401,
  "msg": "未提供认证凭据",
  "data": {}
}
```

**Token 过期（401）：**

```json
{
  "code": 401,
  "msg": "给定令牌对任何令牌类型都无效",
  "data": {}
}
```

**权限不足（403）：**

```json
{
  "code": 403,
  "msg": "您没有权限执行此操作",
  "data": {}
}
```

## 三、统一响应格式

### 3.1 成功响应

所有接口统一返回以下格式：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | HTTP 状态码 |
| `msg` | string | 操作结果描述 |
| `data` | object/array/null | 响应数据 |

### 3.2 分页响应

当接口支持分页且请求中包含 `page` 或 `page_size` 参数时，返回分页格式：

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "count": 100,
    "total_pages": 5,
    "page": 1,
    "page_size": 20,
    "next": "http://localhost:8000/api/v1/assets/assets/?page=2&page_size=20",
    "previous": null,
    "results": [...]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `count` | int | 总记录数 |
| `total_pages` | int | 总页数 |
| `page` | int | 当前页码 |
| `page_size` | int | 每页数量 |
| `next` | string/null | 下一页 URL |
| `previous` | string/null | 上一页 URL |
| `results` | array | 当前页数据列表 |

### 3.3 错误响应

```json
{
  "code": 400,
  "msg": "操作失败",
  "data": {
    "errors": {
      "field_name": ["错误信息1", "错误信息2"]
    }
  }
}
```

### 3.4 业务错误码表

| 错误码 | 异常类 | HTTP 状态码 | 说明 |
|--------|--------|-------------|------|
| E001 | AppValidationError | 400 | 数据验证失败 |
| E002 | NotFoundError | 404 | 资源不存在 |
| E003 | PermissionDeniedError | 403 | 权限不足 |
| E004 | BusinessLogicError | 400 | 业务逻辑错误 |
| E005 | ResourceConflictError | 409 | 资源冲突 |
| E006 | InternalError | 500 | 服务器内部错误 |

### 4.1 认证管理模块

#### POST /api/v1/auth/register/ -- 用户注册

**权限**: AllowAny

**请求体**:

| 字段 | 说明 |
| --- | --- |
| `auth_username` | 用户名 |
| `password` | 密码（write_only），需通过 Django validate_password 验证 |
| `password2` | 确认密码（write_only），必须与 password 一致 |
| `email` | 邮箱 |
| `auth_phone` | 手机号 |

**请求体示例**:

```json
{
  "auth_username": "zhangsan",
  "password": "StrongP@ssw0rd!",
  "password2": "StrongP@ssw0rd!",
  "email": "zhangsan@example.com",
  "auth_phone": "13800138000"
}
```

**业务规则**:
- 注册强制 `auth_is_staff=False`
- `password` 需通过 Django `validate_password` 验证
- 成功返回 201 状态码

## 七、特殊功能说明

### 7.1 分页机制

系统采用自定义分页器 `CustomPageNumberPagination`，具有以下特性：

- **默认每页**: 20 条
- **最大每页**: 100 条
- **参数名**: `page`（页码）、`page_size`（每页数量）
- **智能分页**: 无分页参数时返回全部数据（不分页），有分页参数时启用分页

**使用示例**:

```
# 不分页，返回全部数据
GET /api/v1/assets/assets/

# 分页，返回第 1 页，每页 20 条
GET /api/v1/assets/assets/?page=1

# 分页，返回第 2 页，每页 50 条
GET /api/v1/assets/assets/?page=2&page_size=50
```

### 7.2 过滤搜索

系统使用 `django-filter` + `django-rest-framework` 内置过滤器实现多维度的过滤和搜索。

**精确过滤** (`filterset_fields`):

通过 `DjangoFilterBackend` 实现精确匹配过滤，参数名与字段名一致。

```
GET /api/v1/assets/assets/?asset_current_status=in_store&asset_type_code=AT001
```

**模糊搜索** (`search_fields`):

通过 `SearchFilter` 实现，使用 `search` 参数，在指定字段中进行 `icontains` 查询。

```
GET /api/v1/users/employees/?search=张三
```

**关键词搜索** (`keyword` 参数):

部分视图集支持自定义的 `keyword` 参数，在多个字段中进行 OR 查询。

```
GET /api/v1/assets/assets/?keyword=ThinkPad
GET /api/v1/assets/storages/?keyword=北京
```

### 7.3 排序

通过 `OrderingFilter` 实现，使用 `ordering` 参数。

```
# 按入库日期降序（默认）
GET /api/v1/assets/assets/?ordering=-asset_entry_date

# 按资产编码升序
GET /api/v1/assets/assets/?ordering=asset_code

# 按价格降序
GET /api/v1/assets/assets/?ordering=-asset_purchase_price
```

### 7.4 批量操作

#### 部门批量排序

```
PUT /api/v1/users/departments/sort/
```

一次性更新多个部门的排序值，适用于前端拖拽排序场景。

#### 员工批量排序

```
PUT /api/v1/users/employees/sort/
```

一次性更新多个员工的排序值。

#### 资产批量创建

```
POST /api/v1/assets/assets/
```

传入数组格式的请求体，可一次性创建多个资产记录，后端自动为每个资产生成唯一编码。

#### 硬盘序列号批量保存

```
POST /api/v1/assets/harddisk-sn/batch-save/
```

一次性保存或更新某个资产下的多个硬盘序列号记录。

### 7.5 软删除

系统中大部分资源采用软删除机制（通过 `is_deleted` 字段标记），删除操作不会物理删除数据库记录。

**支持软删除的资源**:
- 部门 (Department)
- 员工 (Employee)
- 仓库 (Storage)
- 资产类型 (AssetType)
- 合同 (Contract)
- 资产 (Asset)
- 出库记录 (OutAsset)
- 回收记录 (RecycleAsset)
- 待报废记录 (DamagedAsset)

**注意**: 操作记录 (AssetOperationLog) 为只读，不支持删除。

### 7.6 资产状态流转

资产在其生命周期中经历以下状态流转：

```
                    +------------------+
                    |    in_store      |
                    |    （在库）       |
                    +--------+---------+
                             |
                             | 出库
                             v
                    +------------------+
                    |    in_use        |
                    |    （在用）       |
                    +--------+---------+
                             |
              +--------------+--------------+
              |                             |
              | 回收                        | 提交报废申请
              v                             v
    +------------------+          +------------------+
    | recycled_pending |          |    damaged       |
    | （已回收待发放）  |          |    （待报废）     |
    +--------+---------+          +--------+---------+
             |                             |
             | 重新发放                    | 审批通过
             v                             v
    +------------------+          +------------------+
    |    in_use        |          |    scrapped      |
    |    （在用）       |          |    （已报废）     |
    +------------------+          +------------------+
                                         ^
    +------------------+                 |
    | recycled_pending |  审批拒绝        |
    | （已回收待发放）  | <---------------+
    +------------------+
```

**状态流转规则**:

| 当前状态 | 目标状态 | 触发操作 |
|----------|----------|----------|
| in_store | in_use | 出库 |
| in_use | recycled_pending | 回收 |
| recycled_pending | in_use | 重新发放 |
| recycled_pending | damaged | 提交报废申请 |
| damaged | scrapped | 审批通过 |
| damaged | recycled_pending | 审批拒绝 |

### 7.7 自动编码生成

系统在创建特定记录时自动生成编码：

| 编码类型 | 格式 | 示例 |
|----------|------|------|
| 资产入库记录编码 | `Entry` + `YYYYMMDDHHmmss` + 8位UUID | `Entry20260523103000a1b2c3d4` |
| 资产编码 | `ASSET-` + `{category}` + `-` + `{type_code}` + `-` + `YYYYMMDD` + `-` + `{random}` + `-` + `{seq}` | `ASSET-hardware-AT001-20260115-abc123-001` |
| 出库记录编码 | `OUT-` + `YYYYMMDD` + `-` + 8位UUID | `OUT-20260523-XXXXXXXX` |
| 回收记录编码 | `RECYCLE-` + `YYYYMMDD` + `-` + 8位UUID | `RECYCLE-20260523-XXXXXXXX` |

> **v1.1.0 变更**: 新增资产编码自动生成格式 `ASSET-{category}-{type_code}-{YYYYMMDD}-{random}-{seq}`；新增回收记录编码格式 `RECYCLE-YYYYMMDD-XXXXXXXX`。

### 7.8 操作日志

系统自动记录资产的关键操作日志，包括：

- **记录时机**: 创建、更新、删除、出库、回收、待报废、已报废、审批
- **记录内容**: 操作前数据、操作后数据、操作人、操作时间、IP 地址
- **查询维度**: 按资产、按操作人、按时间范围、按操作类型、按 LoggingId
- **只读**: 操作日志不支持修改和删除

### 9.3 JavaScript (fetch) 调用示例

```javascript
const BASE_URL = 'http://localhost:8000/api';

// ===== 1. 用户登录 =====
async function login(username, password) {
  const response = await fetch(`${BASE_URL}/auth/login/`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ auth_username: username, password })
  });
  const result = await response.json();
  if (result.code === 200) {
    localStorage.setItem('access_token', result.data.access);
    localStorage.setItem('refresh_token', result.data.refresh);
  }
  return result;
}

// ===== 2. 通用请求封装 =====
async function apiRequest(method, url, data = null) {
  const token = localStorage.getItem('access_token');
  const options = {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {})
    }
  };
  if (data) options.body = JSON.stringify(data);
  const response = await fetch(`${BASE_URL}${url}`, options);
  return await response.json();
}

// ===== 3. 获取资产列表 =====
async function getAssets(page = 1, pageSize = 20) {
  return apiRequest('GET', `/assets/assets/?page=${page}&page_size=${pageSize}`);
}

// ===== 4. 创建出库记录 =====
async function createOutAsset(assetCode, managerJobcode) {
  return apiRequest('POST', '/assets/out-assets/', {
    outasset_code: assetCode,
    outasset_manager_jobcode: managerJobcode,
    outasset_type: 'receive'
  });
}

// ===== 5. 获取仪表盘概览 =====
async function getDashboardOverview() {
  return apiRequest('GET', '/dashboard/overview/');
}

// ===== 6. 刷新 Token =====
async function refreshToken() {
  const refresh = localStorage.getItem('refresh_token');
  const result = await fetch(`${BASE_URL}/auth/token/refresh/`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ refresh })
  }).then(r => r.json());
  if (result.access) {
    localStorage.setItem('access_token', result.access);
  }
  return result;
}

// ===== 7. 退出登录 =====
async function logout() {
  const token = localStorage.getItem('access_token');
  const refresh = localStorage.getItem('refresh_token');
  const result = await apiRequest('POST', '/auth/logout/', { refresh });
  localStorage.removeItem('access_token');
  localStorage.removeItem('refresh_token');
  return result;
}
```

### 9.6 注意事项

1. **日期格式**: 所有日期字段使用 `YYYY-MM-DD` 格式（如 `2026-01-15`）
2. **日期时间格式**: datetime 字段使用 ISO 8601 格式（如 `2026-06-08T10:00:00+08:00`）
3. **金额格式**: 金额字段使用字符串形式的 decimal（如 `"8999.00"`），避免浮点精度问题
4. **分页行为**: 不传分页参数时返回全部数据，传 `page` 或 `page_size` 时启用分页
5. **软删除**: 删除操作为软删除，数据不会物理删除
6. **操作日志**: 系统自动记录操作日志，日志为只读，不可修改或删除
7. **资产编码**: `asset_code` 由后端自动生成，创建后不可修改
8. **自动编码**: `asset_recordcode`、`asset_code`、`outasset_recordcode`、`recycle_record_code` 由系统自动生成
9. **权限控制**: 部门和员工的管理操作（创建/修改/删除）需要管理员权限
10. **Token 安全**: `access_token` 有效期较短（默认 2 小时），过期后需使用 `refresh_token` 刷新
