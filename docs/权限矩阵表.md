# 权限矩阵表

> 适用：资产管理系统后端（Python 3.12+ / Django 6.0 / DRF 3.15+ / PostgreSQL 16）  
> 地位：权限设计、开发、测试与运维的核心依据，所有权限变更必须同步更新本文档。  
> 遵循：`AGENTS.md` 红线、`SECURITY.md` 权限分层要求。

---

## 1. 角色定义

| 角色编码            | 角色名称   | 职责摘要                       |
| --------------- | ------ | -------------------------- |
| `SYS_ADMIN`     | 系统管理员  | 全局配置、用户与角色管理、系统日志；拥有最高权限   |
| `OP_ADMIN`      | 运营管理员  | 业务运营配置、数据监控、普通用户操作审核       |
| `BUSINESS_USER` | 普通业务用户 | 日常业务操作，仅可访问自身或被授权的业务数据     |
| `AUDITOR`       | 审计人员   | 只读权限：查看操作日志、业务数据审计，无任何修改权限 |
| `GUEST`         | 游客     | 未登录用户，仅可访问公开数据             |

## 3. 数据权限规则

### 3.1 行级权限（必须通过 `get_queryset` 和对象级检查实现）

| 角色              | 数据范围                    |
| --------------- | ----------------------- |
| `SYS_ADMIN`     | 全量数据（系统配置、所有用户、所有资产、日志） |
| `OP_ADMIN`      | 全量业务资产数据，不可修改系统配置类数据    |
| `BUSINESS_USER` | 仅自己创建的资产，或运营管理员授权的资产    |
| `AUDITOR`       | 全量只读（按需过滤敏感字段）          |
| `GUEST`         | 无数据访问（仅公开资源）            |

**实现规范**：

- 视图中必须重写 `get_queryset` 按 `request.user` 的部门/角色过滤。
- 涉及单个对象的操作必须调用 `check_object_permissions`。
- 推荐使用 `django-guardian` 管理对象级权限（如资产授权给特定用户/组）。

### 3.2 列级权限（敏感字段控制）

以下敏感字段在序列化时需根据角色动态屏蔽或脱敏：

- 用户密码、Token（所有非系统管理员不可见）
- 数据库连接信息、API 密钥等系统配置
- 资产的采购价、供应商联系方式（仅 `SYS_ADMIN`、`OP_ADMIN` 可查看，`AUDITOR` 不可见原始价格）
- 个人隐私信息（身份证、电话号码部分脱敏）

**实现方式**：

- Serializer 中使用 `SerializerMethodField` 动态返回。
- 或通过 `write_only=True` 对写入开放，读取时限制。

---

## 4. 权限生效机制

- **实时生效**：权限变更后无需用户重新登录，下一个请求即携带更新后的权限。
- **审计留痕**：所有权限的增加、修改、删除操作必须记录到审计日志（含操作人、时间、变更前后内容）。
- **缓存策略**（可选）：若引入 Redis 缓存用户权限，需设计失效机制，确保与数据库一致。

---

## 5. 权限管理维护规则

- 新角色创建：由 `SYS_ADMIN` 发起，并同步更新本文档。
- 权限变更：需留存审批记录，数据库中可扩展 `permission_change_log` 表记录（操作人、时间、变更详情）。
- 定期复核：每季度检查权限矩阵，清理不再使用的权限，修正配置错误。

> 🔴 任何与本文档不一致的权限实现将被视为 Bug，必须修复。
